# Lovable Idea — Cat/Dog MLOps Dashboard

> Paste into Lovable. Build a **front-end demo** with **React + TypeScript + Vite + Tailwind (shadcn/ui) + recharts + lucide-react**, driven by **mock data**. The real backend (FastAPI + MLflow) comes later — put every data access in a typed `src/services/*.ts` layer returning Promises, so it can be swapped to `fetch()` without touching the UI.

## Design system

- **Theme**: clean SaaS look; support **light + dark mode** (persisted). Primary accent **indigo-600**, success **emerald**, warning **amber**, danger **rose**, neutral grays.
- **Surfaces**: cards with `rounded-xl`, `border` + subtle shadow (`shadow-sm`); page background slightly tinted (`bg-muted/40`).
- **Components**: use shadcn/ui — `Button`, `Card`, `Table`, `Dialog`, `Badge`, `Tabs`, `Select`, `Input`, `Slider`/`NumberInput`, `Progress`, `Switch`, `Tooltip`, `Sonner` toasts.
- **Typography**: Inter font; page titles `text-2xl font-semibold`, section labels uppercase `text-xs tracking-wide text-muted-foreground`.
- **Charts**: recharts with indigo area/line fills and rounded axes; tooltips on hover.

## Layout

Left sidebar (~240px, collapsible to icons on mobile) with app title "CatDog MLOps" + 5 nav items (Dashboard, Data Management, Training, Model Registry, Prediction), each with a lucide icon. Top bar (inside content, `sticky`) shows the page title and, on the right, a live **Production version pill** (e.g. `Production: v3 · acc 96.4%`) plus the dark-mode toggle.

## Pages

**1. Dashboard** (overview)
- **4 KPI cards** in a responsive grid: Models registered, Production version (with accuracy), Training runs, Datasets. Each shows a value + a delta/trend hint.
- **Production model card**: as a highlighted card — current version, accuracy, loss, source run id, dataset version, linked CTA "View registry".
- **Recent runs table** (last 5 of `listRuns()`): name, dataset version, accuracy, status badge, timestamp.
- **Accuracy-over-time line chart**: best-run accuracy vs run sequence, showing improvement (91% → 96%).

**2. Data Management**
- **Dataset versions table**: columns = Version, Name, Images, Cats/Dogs (inline mini bar), Status, Created. Status badges: `validated` green, `validating` amber pulse, `invalid` red, `uploading` blue.
- **"Upload dataset" button** → Dialog with: drag-and-drop zone (accept `.zip`), dataset name input, label select, and an **auto-train Switch**. On submit: add a row, run status `uploading` → `validating` → `validated` over ~2s, then a success toast with validation summary ("1,240 images · 98% valid · split 80/20").
- **Validation summary** shown for `validated` rows via expand or tooltip: train/validation counts + class split.

**3. Training**
- **Config form** (card): Dataset version (Select), Pretrained model (Select: MobileNetV2, ResNet50, EfficientNetB0), Epochs (default 10), Learning rate (default 0.0005), Batch size (default 32), Image size (default 224), Run name (auto-suggested, editable). "Start training" validates the form, adds a run with status `queued` → `running` → `finished`, and shows a live progress bar.
- **Runs table**: name, dataset version, epochs/lr/batch, accuracy, loss, val accuracy/loss, status badge (`running` green pulse, `finished` emerald, `failed` rose, `queued` gray), duration, timestamp.
- **Run detail drawer** (click a row): all logged params + metrics, accuracy/loss curve, artifacts list (model summary, confusion-matrix placeholder).
- **Compare**: select 2+ runs → metric side-by-side table + grouped bar chart of accuracy/loss.

**4. Model Registry** (core of the app)
- **Versions table** for `CatDogClassifier`: Version, Stage badge, Accuracy, Loss, Source run id, Dataset version, Created.
- **Stage badges**: `Production` green, `Staging` amber, `Rejected` rose, `Archived` gray — with a subtle info banner: `Train → Register → Evaluate → Approve → Production`.
- **Per-row actions** (kebab menu or inline): Approve → Staging; Reject; **Promote to Production** (auto-demotes the old Production to Archived); Archive. Production row is tagged and can't be rejected/archived until another version is promoted.
- **Compare** selected versions side-by-side (metrics + bar chart).

**5. Prediction**
- **"Serving model" banner**: `Serving: CatDogClassifier v3 (Production)` — updates instantly when the registry changes.
- **Upload** (drag-drop or picker) → image **preview**.
- **"Predict"** → result card: big `Cat` / `Dog` label, confidence bar + %, and serving metadata (model version + run id).
- **Recent predictions** table: thumbnail, result badge, confidence, timestamp. Mock `predict()` so a dog image returns `Dog` ~0.97.

## Data models & mock data

Ship realistic seed data (6 datasets, ~20 runs, 6 model versions, several predictions) so every screen looks populated on first load.

```ts
type Status = 'uploading'|'validating'|'validated'|'invalid';
type RunStatus = 'queued'|'running'|'finished'|'failed';
type ModelStage = 'Production'|'Staging'|'Rejected'|'Archived';

interface DatasetVersion { id: string; version: string; name: string; imageCount: number; cats: number; dogs: number; status: Status; autoTrain: boolean; createdAt: string }
interface TrainingRun { id: string; name: string; datasetVersion: string; modelName: string; epochs: number; learningRate: number; batchSize: number; imageSize: number; accuracy: number /*0-100*/; loss: number; valAccuracy: number; valLoss: number; status: RunStatus; durationSec: number; createdAt: string }
interface ModelVersion { version: string; stage: ModelStage; runId: string; datasetVersion: string; accuracy: number; loss: number; createdAt: string }
interface Prediction { id: string; imageName: string; result: 'cat'|'dog'; confidence: number /*0-100*/; modelVersion: string; createdAt: string }
```

Example seed rows (feel-free to extend):
- Models: `v1 Rejected 91.2%`, `v2 Rejected 94.0%`, `v3 Production 96.4%`, `v4 Staging 95.8%`, `v5 Archived 95.1%`, `v6 Archived 94.6%`.
- Datasets: `v1–v6`, e.g. v6 = "14,000 images, 7,120 cats / 6,880 dogs, validated".

## Service layer (mock → future API)

Keep state in a module store / React context so actions (upload, start training, promote) mutate the same data and the UI updates reactively. Add a small artificial delay (~300–600ms) so loading states are visible.

| Function | Future endpoint |
|---|---|
| `listDatasets()` / `uploadDataset(...)` | `GET,POST /api/datasets` |
| `listRuns()` / `startTraining(cfg)` | `GET /api/runs`, `POST /api/train` |
| `listModelVersions()` / `setModelStage(v, stage)` | `GET /api/models/CatDogClassifier/versions`, `POST .../stage` |
| `predict(image)` | `POST /api/predict` |

## Behaviors

- Status-changing actions (Reject / Promote / Archive) → confirmation dialog + toast on success.
- Promoting to Production updates the top-bar pill, the banner, and the Prediction page instantly.
- Form validation: required fields + numeric ranges (epochs ≥ 1, lr 0–1, batch ≥ 1); inline error messages on invalid input; disabled submit while a run is already `running`.
- Loading: skeleton rows on first fetch of each table; spinner on dialog submit.
- Empty states: icon + one-line text + action button per table.
- Tables scroll horizontally inside their own container (`overflow-x-auto`); no body horizontal scroll.
