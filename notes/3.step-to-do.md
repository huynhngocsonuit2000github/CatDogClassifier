# Step To Do — Cat/Dog MLOps Platform

> Draft implementation plan for the end-to-end Cat/Dog classifier: dataset → transfer learning → MLflow tracking → Model Registry → FastAPI dynamic serving → Docker → UI.
>
> Sources: `0.draft-idea.md` (business + services), `1.gptidea.md` (MLflow-centric architecture), `2.Cat_Dog_MLOps_Project_Implementation_Guide.docx` (6 phases), `3.lovable/` (UI spec).

---

## 1. Goal

Build a reproducible MLOps system that:

1. Trains a Cat/Dog image classifier with **transfer learning** (MobileNetV2).
2. Tracks every run in **MLflow** (parameters, metrics, artifacts, model).
3. Manages model versions in the **MLflow Model Registry**.
4. Serves the **Production** model **dynamically** from the Registry (no hard-coded `model_v3.keras`).
5. Runs reproducibly with **Docker Compose**.
6. Exposes it all through a dashboard.

**End-to-end flow:**

```
Dataset → Training Pipeline → Transfer Learning → MLflow Tracking
        → Model Registry → FastAPI Dynamic Serving → Docker → Prediction
```

## 3. Target architecture

```
                    ┌───────────────────────────────────────────┐
                    │                 Docker Compose            │
                    │                                           │
 Angular UI (src/ui)│   ┌───────────────┐   ┌───────────────┐   │
  (dashboard)  ─────┼──▶│  FastAPI API  │   │  MLflow Server│   │
   REST /predict     │   │  (serving)    │──▶│  (tracking +  │   │
   /datasets /train  │   └───────┬───────┘   │   registry)   │   │
                    │           │           └───┬───────┬───┘   │
                    │           │ load Prod      │       │       │
                    │           │ model from     │       │       │
                    │     Model Registry ◀───────┘       │       │
                    │                                   │       │
                    │              ┌─────────────┐  ┌────┴─────┐ │
                    │              │ PostgreSQL  │  │  MinIO   │ │
                    │              │ backend     │  │ artifact │ │
                    │              │ store       │  │ store    │ │
                    │              └─────────────┘  └──────────┘ │
                    └───────────────────────────────────────────┘
```

- **MLflow Tracking Server** → PostgreSQL (backend store) + MinIO (artifact store)
- **Model Registry** — `CatDogClassifier` v1, v2, v3…
- **FastAPI API** — loads the currently **Production** version, so promotion needs **zero code change**.

## 5. Step-by-step plan

### Phase 0 — Project setup

**Goal:** a clean, cloneable repo layout.

- [ ] Create the backend folder structure alongside the existing UI:
  ```
  CatDogClassifier/
  ├── dataset/            # raw train/validation images (cats/, dogs/)
  ├── trainer/            # training + evaluation code
  │   ├── train.py
  │   ├── evaluate.py
  │   ├── model.py
  │   └── requirements.txt
  ├── api/                # FastAPI serving
  │   ├── main.py
  │   ├── model_loader.py
  │   ├── Dockerfile
  │   └── requirements.txt
  ├── src/ui/             # ✅ Angular app (already built)
  ├── docker-compose.yml
  ├── README.md
  └── .gitignore
  ```
- [ ] Create + activate a Python venv (`trainer/` and `api/` can share one venv or each have one).
- [ ] `pip install tensorflow mlflow fastapi uvicorn python-multipart pillow numpy`.
- [ ] `git init` / commit the UI if not already committed; add `.gitignore` for `__pycache__`, venv, model artifacts, `mlruns/`.

✅ **Expected output:** folder skeleton + working environment; `README.md` stub.

---

### Phase 1 — Dataset + Transfer Learning

**Goal:** a trained Cat/Dog classifier with reproducible training code.

- [ ] Prepare `dataset/` with `train/cats`, `train/dogs`, `validation/cats`, `validation/dogs` (use a Kaggle Dogs-vs-Cats subset; aim ~80/20 split, balanced classes).
- [ ] Write `trainer/model.py`: load MobileNetV2 (ImageNet weights, `include_top=False`), freeze the base, add `GlobalAveragePooling2D` + `Dense(1, sigmoid)` (binary Cat/Dog).
- [ ] Write `trainer/train.py`: image generators with augmentation, config via CLI args/env (dataset dir, epochs, batch size, learning rate, image size), fit, save the model artifact.
- [ ] Evaluate: accuracy, loss, validation accuracy/loss; quick manual sanity check (`cat.jpg → Cat`, `dog.jpg → Dog`).

✅ **Expected output:** `trainer/train.py` + trained model; accuracy/loss + validation metrics logged/printed.

---

### Phase 2 — MLflow Experiment Tracking

**Goal:** every run is tracked and comparable.

- [ ] Start a local MLflow tracking server (`mlflow server`).
- [ ] Create / use the `CatDogClassifier` experiment.
- [ ] In `trainer/train.py`, wrap training with `mlflow.start_run()`:
  - Log **parameters**: epochs, batch size, learning rate, image size, model name.
  - Log **metrics**: accuracy, loss, val_accuracy, val_loss.
  - Log the **model** and useful **artifacts** (summary, sample predictions).
- [ ] Run 2–3 trainings with different hyper-parameters to produce multiple runs.

✅ **Expected output:** MLflow UI showing multiple runs (e.g. Run 1 = 91%, Run 2 = 94%), each with params/metrics/artifacts.

---

### Phase 3 — MLflow Model Registry

**Goal:** versioned models with a clear Production stage.

- [ ] Register the trained model as `CatDogClassifier` (via `mlflow.register_model` or the UI).
- [ ] Produce multiple **versions** from different runs (v1, v2, v3…).
- [ ] Promote one version to **Production**.
- [ ] Keep model paths out of the application code — the API will resolve the model **by name + stage**, not by file path.

✅ **Expected output:** `CatDogClassifier` with v1/v2/v3; a selected Production version; the API references the Registry, and changing Production requires no API code change.

---

### Phase 4 — FastAPI Dynamic Serving

**Goal:** `POST /predict` serves the current Production model automatically.

- [ ] Write `api/model_loader.py`: use `mlflow.pyfunc.load_model("models:/CatDogClassifier/Production")`.
- [ ] Write `api/main.py`:
  - `POST /predict` — accept an image upload, preprocess (resize to model input size, normalize), run inference, return `{ prediction: "cat"|"dog", confidence: 0.97 }`.
  - Optional `GET /health`.
- [ ] Verify: call `POST /predict` → correct class + confidence.
- [ ] Verify the _dynamic_ part: promote v1→v2 Production in the Registry, call `/predict` again → the new model is used **without changing code**.

✅ **Expected output:** working FastAPI service that always serves the current Production model.

---

### Phase 5 — Docker + Reproducibility

**Goal:** another person can clone and run everything.

- [ ] Upgrade MLflow to PostgreSQL (backend store) + MinIO (artifact store) via `docker-compose.yml`.
- [ ] Write `api/Dockerfile` (FastAPI service).
- [ ] Write `docker-compose.yml` services: `mlflow`, `postgres`, `minio`, `api` (and optionally the built `src/ui` static output behind nginx).
- [ ] Document config: ports, env vars, dependencies, startup order.
- [ ] Write `README.md`: setup, training, registry, serving, prediction steps + architecture diagram.

✅ **Expected output:** `docker-compose.yml` + Dockerfiles; reproducible runtime; README an outsider can follow to clone → run.

---

### Phase 6 — Wire the UI to the API

**Goal:** the Angular dashboard talks to the real backend instead of mock data.

- [ ] Add API base URL config + an HTTP service layer in `src/ui` (keep the current `store.ts` shape — the UI already reads from typed signals).
- [ ] Replace mock calls with `fetch()`:
      | UI function | API endpoint |
      |---|---|
      | `listDatasets()` / `uploadDataset(...)` | `GET, POST /api/datasets` |
      | `listRuns()` / `startTraining(cfg)` | `GET /api/runs`, `POST /api/train` |
      | `listModelVersions()` / `setModelStage(v, stage)` | `GET /api/models/CatDogClassifier/versions`, `POST …/stage` |
      | `predict(image)` | `POST /api/predict` |
- [ ] Keep mock data as a dev fallback flag so the UI can still run without the backend.
- [ ] Handle CORS in FastAPI (or proxy through nginx).

✅ **Expected output:** the UI reflects live backend state; uploading an image through the UI returns a real Cat/Dog prediction.

## 8. Strategy notes

- **One phase at a time** — verify its expected output before moving on.
- **Don't add** Kubernetes, DVC, Azure, or drift detection initially — not required by the rubric; add later only after the core is stable.
- **Start simple, then harden:** local MLflow filesystem backend first → PostgreSQL + MinIO in Phase 5.
- The **UI is already done** with a clean mock service layer, so the backend can be built and verified independently in parallel with any UI polish.
