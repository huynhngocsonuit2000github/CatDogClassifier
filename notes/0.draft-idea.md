# Application Business - User cases

The application is an end-to-end MLOps platform for a Cat/Dog image classifier. It targets three kinds of users:

- **Data manager** — upload, validate, and version the image datasets used for training.
- **ML engineer** — configure and launch training runs, track experiments, register models, and promote the best version to Production.
- **End user / consumer** — upload a single image and receive a Cat/Dog prediction with confidence.

Concrete user cases:

1. As a data manager, I want to upload a dataset and have it validated and versioned, so that I can track exactly which data each model was trained on.
2. As an ML engineer, I want to launch a training run against a dataset version with tunable parameters (epochs, learning rate, batch size, image size, pretrained model name), so that I can experiment to improve the model.
3. As an ML engineer, I want the system to **auto-train** when a new dataset version is committed (and also support **manual** training), so that models stay up to date without manual steps.
4. As an ML engineer, I want every run's parameters, metrics, and artifacts recorded in MLflow, so that I can compare and reproduce experiments.
5. As an ML engineer, I want trained models registered as versioned artifacts (v1, v2, v3…) in the Model Registry, so that I can manage the model lifecycle separately from application code.
6. As a reviewer, I want to compare and approve/reject model versions, so that only a validated model is promoted to Production.
7. As an end user, I want to upload an image and get back "cat" or "dog" with a confidence score, so that I can use the model in a real app.

# Service and description

The platform is split into three services plus a dashboard.

## Data Management service
Manages data validation, collection, and versioning. Each dataset is stored as a versioned artifact (v1, v2, v3…). A new dataset version can trigger auto-training or be picked up manually.

- Validate uploaded images (format, class labels Cats/Dogs, train/validation split).
- Version datasets so every training run references an explicit **dataset version**.
- Trigger **auto-train** when a new version is committed, or allow **manual** training against a chosen version.

## Training service
Exports an API to train the model from a dataset version and a set of parameters (epochs, learning rate, batch size, image size, pretrained model name). It also handles model approval so the Production service knows which model to use.

- Launch a training run for a given dataset version + hyper-parameters (transfer learning on MobileNetV2).
- Log parameters, metrics, and the model artifact to **MLflow Experiment Tracking**.
- Register each trained model as a new version of `CatDogClassifier` in the **Model Registry**.
- Provide **approve / reject** actions; only the approved (Production) version is served.

## Prediction service
Exposes an inference API that serves the current Production model dynamically. This is the requirement of the assignment: no hard-coded `model_v3.keras` path.

- `POST /predict` accepts an image upload.
- Loads the **Production** version of `CatDogClassifier` from the MLflow Model Registry (not a local file path).
- Preprocesses the image and returns `prediction` (cat/dog) + `confidence` (e.g. `prediction=cat, confidence=0.97`).
- When the Production version changes, the API serves the new model with **zero code change**.

# Final app

The final app is a dashboard wrapping the three services, backed by an MLflow Tracking Server, a PostgreSQL backend store, and a MinIO artifact store (run with Docker Compose).

```
┌─────────────────────────────────┐
│ Dashboard                       │
├─────────────────────────────────┤
│ Data Management                 │
│ → Dataset versions              │
│ → Upload / validate new data    │
├─────────────────────────────────┤
│ Training                        │
│ → Training configuration        │
│ → Training runs (MLflow logs)   │
├─────────────────────────────────┤
│ Model Registry                  │
│ → Model versions                │
│ → Compare                       │
│ → Approve / Reject              │
│ → Deploy to Production          │
├─────────────────────────────────┤
│ Prediction                      │
│ → Upload image                  │
│ → Cat / Dog + confidence        │
└─────────────────────────────────┘
```

End-to-end flow:

```
Dataset → Training Pipeline → MLflow Tracking → Model Registry → Production → FastAPI Serving → Prediction
```
